# The 349.5 bump: what broke and what fixed it

348.5 → 349.5 is not a routine bump. Discord adopted the React Compiler in
this release (see `REACT_COMPILER_3495.md`), which renumbered every function
*and* removed the names the old remap depended on.

## What actually broke

Running the suite unmodified against 349.5 gives **0 FAIL, 148 SKIP** — the
patcher correctly refuses to write anything rather than corrupting the bundle.
The skips were concentrated:

| Section | OK | SKIP |
|---|---|---|
| `JS TELEMETRY / LOGGING (Hermes bytecode)` | 1 | **135** |
| `JS FEATURE REMOVAL (body edits)` | 0 | **8** |
| everything else (manifest, Sentry, AppsFlyer, watchdog, ODB, OTA, EGL, jank, foreground service, blocklist, …) | 93 | 0 |

So only the two JavaScript sections need re-deriving; the smali side survives
bumps unchanged (all 41 `com/discord/...` targets present, `jank_stats` 2/2,
`EglRenderer` 8/8, `ThreadUtils` 9/9).

## Re-deriving the Hermes targets

Two resolvers, merged:

- **`tools/remap_hermes.py`** — by function *name*, then id-window + bytecode
  similarity for ambiguous names. Resolves the analytics/logging methods, which
  keep their names. Extended this round to cover **all six** `*TARGETS` tables
  (it previously did three, so `FALSE_TARGETS` / `NULL_TARGETS` /
  `OBJECT_FALSE_TARGETS` silently kept stale ids and skipped on every bump).
  `--emit-json` writes the mapping for merging.

- **`tools/remap_by_module.py`** — by **Metro module path** plus the chain of
  `CreateClosure` indices down from the factory. This is what resolves the
  React Compiler components, which have no name left to match on but are still
  exactly where the module puts them. `groups_of()` collapses each compiled /
  uncompiled pair into one logical entry so an index recorded against 348.2
  keeps its meaning.

- **`tools/merge_remap.py`** — merges the two, reports agreements and
  conflicts, and rewrites `core.py`. It also appends the second row for each
  React Compiler pair.

Result: **125 of 136 targets resolved**, with 41 cases where both methods
independently agree.

### The one conflict worth knowing about

`BalanceWidgetMenu` (63907): the name match found `70912`, the structural walk
found the pair `(70916, 70915)`. The module has **four** closure groups against
**four** old closures — an exact positional match — while `70912` is a
*differently-named sibling* in the same module that happens to carry the same
name. Structure wins. This is the class of error the merge exists to surface:
a wrong id here does not fail, it stubs the wrong function.

## Two bugs in the patch suite that 349.5 exposed

### 1. `PROMISE_HASM` used `GetByIdShort` and rendered the wrong property

The promise stub is

```
GetGlobalObject r0
TryGetById    r1, r0, 0, "Promise"
GetByIdShort  r0, r1, 0, "resolve"
Call1         r0, r0, r1
Ret r0
```

Byte-identical HASM renders **`Promise.resolve()` on 348.2** and
**`Promise.hash()` on 349.5**. Asking for `"race"` yields `Promise.value()` —
a name never requested. The short form's 8-bit property operand is being
resolved out of the function's *existing* inline-cache region, which
`patch-function` cannot rewrite, so the result is not even stable per function.

The long form is unaffected: `GetById` renders exactly the property asked for,
at any cache index (verified for `resolve` / `race` / `all` at indices 0 and 1).
Cache index 0 is kept because the existing `CACHE_OPCODE` guard already proves
the function owns an inline-cache region.

Before: **17 `PROMISE_TARGETS` failed verification**. After: **0**.

### 2. Components are anonymous now, and the guard rejected them

The patcher verified each target by checking the decompiled body contained
`function <name>(`. From 349.5 a React Compiler component is an arrow passed to
`memo()`, so the decompiler names it `f<id>` and the name in our table is the
*old* one — every one of those targets skipped, including ones the structural
remap had correctly resolved. Both the pre-patch and post-patch checks now also
accept `function f<fn>(`, which still requires the id to exist and to be
anonymous. Identity for those targets comes from the module-path chain that
produced the id, not from a name that no longer exists.

`tools/verify-stubs.py` was changed to match.

## Where it landed

```
Hermes no-op'd at bytecode level: 137 function(s), 21 id(s) did not match
CORE DONE: 64 OK, 0 FAIL
```

From 1 stubbed function on the untouched suite to 137.

## Still open

**21 Hermes targets skip**, in three groups:

1. **Module gone in 349.5** — `OrbsBalance`, `OrbsPriceTag`, `WrappedProfileEffect`,
   `BalanceWidgetMenuWrapper` and `CollectiblesShopInternal` have no module path
   *and* no name string anywhere in the bundle. Discord removed or renamed them,
   so these need re-deriving from scratch (or dropping — if the feature is gone
   there is nothing to hide).
2. **Shared bodies** — `AddToWishlistGrid` shares its body with **358** other
   functions, `MobileShopButtonCoachmark` with 1, `onPostConnectionOpen` with 2.
   These are trivial closures that the React Compiler emits by the thousand;
   patching the body would patch all the sharers.
3. **Count drift** — modules whose closure count changed, so position alone is
   ambiguous: `QuestHomeOrbShopCarousel` (8→9), `EditSection` (5→7),
   `CollectiblesShopV2` (2→3), `QuestHomeSetting` (1→2),
   `hasSocialLayerStorefront` (33→29), `useShouldShowQuestsActivityPanelItem`
   (59→61).

**All 8 HASM body edits skip.** They store an exact before-image and it no
longer matches, which is the guard working: *"the bundle drifted; re-derive the
edit, do not force it"*. These are the Wishlist tab, the Quests floating-nav
button, the friends' Spotify activity row, and the three billing Settings rows.
Re-deriving means re-running the generator against the 349.5 body and
re-checking `bad_jumps()` — and they must stay **byte-neutral** (see
`HBC_BODY_EDIT_HAZARD.md`).

## Reproducing

```sh
scripts/01-decode.sh build/alpha3495

# remap, against the PRISTINE old bundle, not a patched tree
tools/remap_by_module.py extract <old>/index.android.bundle --out /tmp/remap_map.json
tools/remap_by_module.py apply   <new>/index.android.bundle --map /tmp/remap_map.json --out /tmp/remap_struct.json
tools/remap_hermes.py            <old>/index.android.bundle <new>/index.android.bundle --emit-json /tmp/remap_name.json
tools/merge_remap.py --names /tmp/remap_name.json --struct /tmp/remap_struct.json --write

scripts/02-patch.sh build/alpha3495
scripts/03-build.sh  build/alpha3495
```

Always extract the *old* bundle from its source APK rather than using
`build/<ver>/decompiled/` — that tree has been patched in place, so its bodies
are stubs and bytecode matching against it is meaningless. `build/alpha3482/`
is in exactly that state; its APK still holds the pristine copy.
